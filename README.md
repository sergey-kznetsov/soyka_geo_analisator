# СОЙКА UDS Development

**СОЙКА UDS Development** — отдельная серверная программа для сбора и анализа городских комментариев, обращений, отзывов и других текстовых сообщений, связанных с адресом или территорией.

Программа является специализированным вычислительным модулем экосистемы **Geo Analyzer**. У СОЙКИ нет собственного пользовательского SaaS-интерфейса и она не дублирует функции Geo Analyzer.

> Этот README является основным документом проекта. Перед каждой рабочей сессией по развитию репозитория необходимо сначала сверяться с ним. Изменения архитектуры, границ ответственности и ключевого поведения программы должны фиксироваться здесь.

## Статус проекта

Репозиторий содержит импортированный исходный код исследовательского проекта SOIKA. В исходной реализации уже присутствуют классификация текстов, уточнение тем, извлечение адресов, геокодирование, тематическая кластеризация, моделирование событий и расчёт рисков.

Текущий исходный код является исследовательским прототипом, а не завершённой серверной программой. Цель этого репозитория — на его основе создать полноценную рабочую версию **СОЙКА UDS Development** для серверного использования совместно с Geo Analyzer.

## Основная архитектура

В системе существует один пользовательский интерфейс — SaaS-интерфейс Geo Analyzer.

```text
Пользователь
    ↓
SaaS-интерфейс Geo Analyzer
    ↓
Ввод адреса или координат
    ↓
Checkbox «Добавить статистику СОЙКА»
    ↓
Backend Geo Analyzer
    ├── основной геоанализ
    └── запуск СОЙКА UDS Development
              ↓
       сбор и анализ комментариев
              ↓
       структурированный результат
    ↓
Общий отчёт Geo Analyzer
    └── дополнительная вкладка СОЙКА
```

Пользователь не взаимодействует с СОЙКОЙ напрямую. Geo Analyzer передаёт ей адрес, координаты и параметры анализа. СОЙКА выполняет собственный аналитический процесс и возвращает данные, которые Geo Analyzer отображает в дополнительной вкладке общего отчёта.

## Граница ответственности

### Geo Analyzer отвечает за

- авторизацию пользователей;

- запуск общего анализа;
- отображение статуса;
- основную карту;
- формирование общего отчёта;
- дополнительную вкладку СОЙКА.

### СОЙКА отвечает за

- получение задания от backend Geo Analyzer;
- запуск подключённых парсеров;
- сбор комментариев и сообщений;
- очистку и нормализацию данных;
- удаление дубликатов;
- классификацию сообщений;
- уточнение тем;
- извлечение адресов и городских объектов;
- OSM-геокодирование;
- пространственную фильтрацию;
- тематическую кластеризацию;
- определение событий;
- определение связей между событиями;
- расчёт аналитических показателей;
- расчёт приоритета и риска;
- оценку покрытия исходных данных;
- возврат структурированных данных в Geo Analyzer.

## Итоговое определение программы

**СОЙКА UDS Development** — специализированная серверная программа, которая получает от Geo Analyzer адрес, координаты и территорию анализа, собирает относящиеся к этой территории городские комментарии, очищает и классифицирует их, уточняет тематику, определяет адресные упоминания, привязывает сообщения к OpenStreetMap, объединяет их в события, рассчитывает показатели и возвращает структурированные данные для дополнительной вкладки общего отчёта Geo Analyzer.

Единственным пользовательским интерфейсом системы остаётся Geo Analyzer. СОЙКА выполняет роль отдельного вычислительного и аналитического модуля.

## Полный рабочий процесс

```text
Получение адреса, координат и территории от Geo Analyzer

        ↓

        ↓
Сбор комментариев и сообщений
        ↓

        ↓

        ↓
Определение уточнённых тем
        ↓
Извлечение адресов и городских объектов
        ↓
Нормализация адресов
        ↓
Геокодирование и проверка через OSM
        ↓
Пространственная фильтрация
        ↓

        ↓

        ↓

        ↓

```

## Входное задание от Geo Analyzer

СОЙКА не запрашивает адрес у пользователя. Она получает готовое задание от backend Geo Analyzer.

Рекомендуемая структура задания:

```json
{
  "analysis_id": "a8f31d42",
  "address": "Ижевск, Пушкинская улица, 277",
  "latitude": 56.8701,
  "longitude": 53.2143,
  "city": "Ижевск",
  "radius_meters": 1500,
  "territory_geojson": null,
  "period_from": "2026-05-01",
  "period_to": "2026-08-03",
  "sources": ["source_1", "source_2"],
  "options": {}
}
```

Предпочтительно передавать одновременно адрес и координаты:

- адрес используется для поисковых запросов и текстового сопоставления;
- координаты используются для точной пространственной фильтрации;
- город ограничивает область поиска улиц и объектов;
- радиус или GeoJSON-полигон задаёт территорию анализа;
- временной период ограничивает собираемые данные;
- список источников определяет разрешённые парсеры.

## Функции программы

### 1. Получение и проверка задания

СОЙКА должна:

- принять идентификатор анализа;
- проверить обязательные поля;
- проверить координаты, адрес, период и геометрию;
- сформировать внутренний контекст выполнения;
- отклонить некорректное задание с понятным описанием ошибки;
- обеспечить повторяемость задания по его идентификатору.

### 2. Формирование территории анализа

На основании входных данных программа формирует рабочую область:

- точка;
- адрес;
- здание;
- улица;
- квартал;
- район;
- территория в заданном радиусе;
- произвольный полигон;
- границы населённого пункта.

Geo Analyzer передаёт исходный адрес, координаты и при наличии геометрию территории. Дальнейшую работу с географическим контекстом СОЙКА выполняет самостоятельно.

### 3. Работа с OpenStreetMap

СОЙКА использует собственный географический контур на базе OpenStreetMap.

Основные инструменты:

- OSMnx — дорожный граф и пространственная структура;
- Overpass — улицы, здания, границы и городские объекты;
- Nominatim — геокодирование адресов;
- GeoPandas — обработка пространственных таблиц;
- Shapely — геометрические операции.

СОЙКА не должна получать инфраструктурные данные или результаты основного анализа из Geo Analyzer. От Geo Analyzer ей передаются только исходные параметры задания.

### 4. Формирование поисковых запросов

Перед запуском парсеров программа формирует набор поисковых выражений:

- полный адрес;
- название улицы;
- номер дома;
- название района;
- название объекта;
- варианты написания адреса;
- сокращения;
- склонённые формы названий;
- старые и альтернативные названия;
- соседние улицы;
- городские ориентиры;
- координаты и геометки;
- ключевые слова, связанные с территорией.

Для адреса `Ижевск, Пушкинская улица, 277` возможны варианты:

```text
Пушкинская 277
ул. Пушкинская, д. 277
дом 277 по Пушкинской
Пушкинская улица
возле дома 277
район Пушкинской 277
```

### 5. Реестр и запуск парсеров

В программе должен существовать единый интерфейс парсеров и отдельные адаптеры для каждого источника.

Возможные источники:

- городские порталы;
- сайты отзывов;
- страницы организаций;
- социальные сети;
- публичные каналы и сообщества;
- системы обращений граждан;
- новостные сайты;
- форумы;
- комментарии под публикациями;
- открытые наборы данных;
- CSV;
- Excel;
- JSON;
- ранее сохранённые выгрузки.

Каждый источник подключается отдельным адаптером и должен соблюдать правила доступа, ограничения и разрешённые способы получения данных соответствующей площадки.

Единая структура собранного сообщения:

```json
{
  "source": "city_portal",
  "external_id": "comment-12345",
  "text": "У дома 277 по Пушкинской снова затопило двор",
  "published_at": "2026-08-01T12:30:00Z",
  "url": "https://example.org/comment/12345",
  "author_id": "anonymous-hash",
  "latitude": null,
  "longitude": null,
  "metadata": {}
}
```

### 6. Очистка и нормализация данных

Перед аналитической обработкой программа должна:

- удалить HTML-разметку;
- очистить служебные символы;
- нормализовать Unicode и кодировку;
- привести даты к единому формату;
- отделить текст автора от цитат и ответов;
- удалить технический текст;
- определить пустые и повреждённые сообщения;
- определить язык;
- сохранить оригинальный текст;
- сформировать очищенную версию для моделей.

Оригинал сообщения не изменяется и хранится для проверки результата.

### 7. Дедупликация

СОЙКА должна выявлять:

- совпадение идентификатора сообщения;
- совпадение ссылки и источника;
- полное совпадение текста;
- совпадение нормализованного текста;
- смысловые дубликаты;
- повторную публикацию одного сообщения на разных ресурсах.

Необходимо различать технический дубль и отдельное повторное обращение по той же проблеме.

### 8. Классификация городских сообщений

Существующий классификатор SOIKA используется для определения основной категории сообщения.

Примеры категорий:

- жилищно-коммунальное хозяйство;
- благоустройство;
- безопасность;
- транспорт;
- дороги;
- здравоохранение;
- образование;
- социальная защита;
- строительство;
- обращение с отходами;
- экология;
- энергетика;
- другие городские функции.

Для каждого сообщения возвращаются:

- основная категория;
- вероятность результата;
- альтернативные категории;
- версия модели;
- признак недостаточной уверенности.

Пример:

```json
{
  "category": "ЖКХ",
  "confidence": 0.91,
  "alternatives": [
    {
      "category": "Благоустройство",
      "confidence": 0.07
    }
  ],
  "model_version": "text_to_function_v2@revision"
}
```

### 9. Уточнение темы

После общей категории СОЙКА определяет более конкретную тему сообщения.

Примеры для категории `ЖКХ`:

- отопление;
- горячая и холодная вода;
- водоотведение;
- затопление;
- канализация;
- содержание дома;
- лифты;
- освещение подъезда;
- уборка территории;
- вывоз мусора.

Примеры для категории `Дороги`:

- ямы;
- разрушение покрытия;
- отсутствие тротуара;
- гололёд;
- затопление дороги;
- отсутствие освещения;
- дорожная разметка;
- светофор;
- опасный перекрёсток.

Результат содержит тему, оценку уверенности, альтернативы и версию модели.

### 10. Извлечение адресов и объектов

Программа анализирует текст и извлекает географические сущности:

- город;
- район;
- улицу;
- переулок;
- проспект;
- шоссе;
- набережную;
- номер дома;
- корпус;
- строение;
- перекрёсток;
- остановку;
- школу;
- больницу;
- торговый центр;
- парк;
- площадь;
- вокзал;
- станцию;
- предприятие;
- городской объект;
- ориентир.

Примеры сообщений:

```text
На Пушкинской возле дома 277 затопило дорогу.
Не работает светофор на перекрёстке Кирова и Коммунаров.
Возле школы № 27 не убирают снег.
У Центральной площади разбит тротуар.
```

СОЙКА должна распознавать как полный адрес, так и неполное описание места.

### 11. Нормализация адресов

Найденные адресные элементы приводятся к единому виду.

Обрабатываются:

- сокращения;
- опечатки;
- склонения;
- разговорные варианты;
- отсутствие типа улицы;
- переставленные части адреса;
- старые названия;
- альтернативные названия;
- корпуса и строения;
- неоднозначные названия;
- местные неофициальные топонимы.

Пример:

```text
Исходное упоминание: «на Пушкинской у 277 дома»
Нормализованный адрес: «Ижевск, Пушкинская улица, дом 277»
```

### 12. OSM-геокодирование

После нормализации СОЙКА определяет координаты адреса или объекта.

Порядок разрешения:

1. локальный кеш;
2. локальные справочники улиц и объектов;
3. данные OpenStreetMap;
4. Nominatim;
5. Overpass и пространственная проверка кандидатов.

Для каждого результата возвращаются:

- широта;
- долгота;
- нормализованный адрес;
- тип объекта;
- уровень точности;
- источник координат;
- оценка уверенности;
- альтернативные кандидаты.

Уровни точности:

```text
building
street
intersection
poi
district
city
unknown
```

### 13. Пространственная фильтрация

После геокодирования СОЙКА проверяет, относится ли сообщение к заданной территории.

Сообщение может быть:

- внутри радиуса;
- внутри переданного полигона;
- на анализируемой улице;
- в анализируемом здании;
- рядом с указанным объектом;
- за пределами территории;
- географически неопределённым.

Для каждого сообщения сохраняется причина включения или исключения.

Совпадение только по названию города недостаточно для автоматического включения сообщения в результат.

### 14. Сообщения без точного адреса

Если в комментарии нет полного адреса, СОЙКА использует дополнительные признаки:

- район;
- организацию;
- остановку;
- городской объект;
- геометку источника;
- координаты публикации;
- название сообщества;
- контекст родительской публикации;
- адрес страницы или организации;
- связанные комментарии.

Если территорию нельзя определить достоверно, сообщение сохраняется отдельно с низкой географической уверенностью и не должно искажать точную статистику.

### 15. Тематическая кластеризация

СОЙКА объединяет близкие по смыслу сообщения.

Для кластеризации могут использоваться:

- текстовые эмбеддинги;
- BERTopic;
- HDBSCAN;
- UMAP;
- категория и тема;
- адрес;
- пространственная близость;
- временная близость;
- смысловая близость.

Пример близких сообщений:

```text
Не работает освещение возле дома.
Уже неделю темно во дворе.
На фонарях возле дома нет света.
```

### 16. Определение событий

Событие — группа сообщений, связанных общей территорией, категорией, темой, смыслом и временным периодом.

Пример:

```text
Адрес: Пушкинская улица, 277
Категория: ЖКХ
Тема: затопление двора
Количество сообщений: 8
Первое сообщение: 25 июля 2026 года
Последнее сообщение: 4 августа 2026 года
Статус: active
```

По одному адресу могут одновременно существовать разные события, например затопление, неработающий лифт и невывоз мусора. Они не должны объединяться только из-за совпадения адреса.

### 17. Связи между событиями

СОЙКА выявляет связи по следующим признакам:

- общая территория;
- общая причина;
- общая категория;
- временная последовательность;
- повторяемость;
- распространение на соседние объекты;
- совпадающие участники или источники;
- смысловая близость.

Например, затопление дороги, переполненная ливневая канализация и затопление двора могут образовывать связанную проблемную цепочку.

### 18. Аналитические показатели

СОЙКА рассчитывает:

- количество собранных сообщений;
- количество релевантных сообщений;
- количество геокодированных сообщений;
- долю сообщений с точным адресом;
- распределение по категориям;
- распределение по темам;
- динамику по времени;
- количество активных событий;
- интенсивность события;
- длительность события;
- повторяемость;
- территориальную концентрацию;
- скорость роста количества сообщений;
- долю повторных обращений;
- уверенность классификации;
- уверенность геокодирования;
- качество покрытия источниками.

### 19. Приоритет и риск

СОЙКА рассчитывает относительный приоритет событий и территорий.

При расчёте учитываются:

- количество сообщений;
- частота сообщений;
- длительность проблемы;
- рост активности;
- категория проблемы;
- потенциальная опасность;
- количество затронутых объектов;
- пространственный масштаб;
- повторяемость;
- актуальность;
- уверенность классификации;
- уверенность геокодирования;
- качество исходных данных.

Формула, коэффициенты и версия алгоритма должны сохраняться вместе с результатом. Расчёт должен быть прозрачным и воспроизводимым.

Отсутствие сообщений нельзя автоматически считать отсутствием проблемы.

### 20. Оценка покрытия данных

СОЙКА отдельно возвращает качество и полноту исходных данных:

- запрошенные источники;
- доступные источники;
- недоступные источники;
- период фактического покрытия;
- дату последнего обновления;
- количество собранных сообщений;
- количество исключённых сообщений;
- количество негеокодированных сообщений;
- количество результатов с низкой уверенностью;
- ограничения и ошибки парсеров.

Показатели покрытия обязательны, поскольку нулевой результат может означать как отсутствие сообщений, так и отсутствие доступа к данным.

### 21. Хранение данных

СОЙКА должна сохранять:

- исходные задания;
- исходные комментарии;
- очищенные тексты;
- сведения об источниках;
- результаты классификации;
- результаты уточнения тем;
- адресные сущности;
- координаты;
- результаты пространственной фильтрации;
- события;
- связи;
- показатели риска;
- предупреждения и ошибки;
- версии моделей;
- версии алгоритмов;
- журнал выполнения.

Хранилище необходимо для повторного использования данных, аудита и предотвращения повторной обработки.

### 22. Кеширование

Кешируются:

- результаты геокодирования;
- данные OSM;
- границы территорий;
- дорожные графы;
- справочники улиц и объектов;
- результаты классификации;
- загруженные сообщения;
- результаты предыдущих запусков;
- файлы моделей.

### 23. Управление моделями

Для каждой модели должны фиксироваться:

- название;
- точная версия;
- ревизия или commit hash;
- дата установки;
- контрольная сумма;
- локальный путь;
- параметры запуска;
- совместимая версия Python;
- совместимые версии библиотек.

Модели загружаются один раз при запуске рабочего процесса, а не для каждого сообщения.

### 24. Серверное выполнение

СОЙКА работает как отдельный серверный процесс или worker и должна поддерживать:

- получение нового задания;
- очередь заданий;
- фоновую обработку;
- обновление статуса;
- отмену задания;
- повторный запуск;
- восстановление после сбоя;
- обработку ошибок;
- ограничение параллельных задач;
- контроль памяти и процессора;
- использование GPU при наличии.

Работа СОЙКИ не должна блокировать основной процесс Geo Analyzer.

### 25. Статусы выполнения

Поддерживаемые статусы:

```text
queued
preparing
collecting
preprocessing
classifying
geocoding
filtering
detecting_events
calculating
completed
completed_with_warnings
failed
cancelled
```

Geo Analyzer использует эти статусы для отображения прогресса пользователю.

### 27. Географические данные для карты

СОЙКА возвращает GeoJSON со следующими типами объектов:

- точки сообщений;
- точки событий;
- здания;
- участки улиц;
- перекрёстки;
- полигоны концентрации;
- зоны событий;
- связи между событиями;
- территории с повышенным риском.

Отображение, стилизация и управление слоями выполняются в Geo Analyzer.

### 28. Ошибки и предупреждения

СОЙКА должна возвращать причины неполного результата:

- источник недоступен;
- достигнут лимит запросов;
- недостаточно сообщений;
- адрес неоднозначен;
- часть сообщений не геокодирована;
- классификация имеет низкую уверенность;
- территория слишком велика;
- данные устарели;
- анализ выполнен только по части источников.

Ошибка СОЙКИ не должна уничтожать основной отчёт Geo Analyzer. Основной геоанализ должен завершиться, а вкладка СОЙКА должна показать ошибку или неполный результат.

## Интеграция с Geo Analyzer

GitHub используется для хранения, версионирования и развёртывания исходного кода. Во время анализа Geo Analyzer не обращается к GitHub.

На сервере СОЙКА может быть установлена:

- отдельным Python-пакетом;
- в отдельной серверной папке;
- отдельным Docker-контейнером;
- отдельным worker-процессом.

Рекомендуемая серверная схема:

```text
geo-analyzer-web
geo-analyzer-worker
soika-worker
database
redis
shared-storage
```

Способ внутреннего обмена между backend Geo Analyzer и СОЙКОЙ определяется при реализации серверной инфраструктуры. Это может быть внутренняя очередь задач, локальный сервис, Unix socket или иной непубличный транспорт.

Внешний публичный интерфейс СОЙКИ не требуется.

## Правила разработки

1. Перед началом задачи необходимо прочитать этот README и проверить, соответствует ли задача назначению СОЙКИ.

## Исходный проект SOIKA

Репозиторий основан на публичном проекте SOIKA, разработанном для выявления точек общественной активности, связанных объектов городской среды и социальных рисков с применением методов NLP к сообщениям граждан на открытых коммуникационных площадках.

В исходной версии присутствуют три основных направления:

- классификация городских сообщений;
- геолокация адресных упоминаний;
- моделирование событий и расчёт рисков.

Используемые подходы и технологии включают BERT/RuBERT, Flair, Natasha, BERTopic, HDBSCAN, UMAP, GeoPandas, Shapely, OSMnx, Overpass и Nominatim.

Импортированный код сохраняется как технологическая основа и источник алгоритмов. Перед производственным использованием он должен быть переработан, протестирован и адаптирован к целевой архитектуре СОЙКА UDS Development.

Дополнительная информация об источнике импорта находится в файлах [UPSTREAM.md](UPSTREAM.md) и [IMPORT_NOTES.md](IMPORT_NOTES.md).
