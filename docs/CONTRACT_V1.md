# Контракт Geo Analyzer ↔ СОЙКА, версия 1.0.0

## Назначение

Этот документ фиксирует версионированный, независимый от транспорта контракт между backend Geo Analyzer и серверной программой СОЙКА UDS Development.

На данном этапе изменяется только репозиторий СОЙКИ. Репозиторий и работающий SaaS-сервис Geo Analyzer 2 не изменяются. Подключение Geo Analyzer будет выполняться отдельным этапом после согласования контракта.

Контракт не определяет HTTP API, файловую очередь, Unix socket или другой способ доставки. Один и тот же JSON-документ должен использоваться при любом выбранном транспорте.

## Версия

Текущая версия контракта: `1.0.0`.

Каждый документ содержит поле:

```json
{
  "contract_version": "1.0.0"
}
```

СОЙКА отклоняет неизвестные версии. Обратная совместимость определяется по явно перечисленному набору поддерживаемых версий, а не только по совпадению major-версии.

Изменение обязательных полей, смысла существующего поля или допустимых значений требует новой версии контракта.

## Публичные документы

Контракт включает три типа сообщений:

1. `analysis.request` — задание на анализ.
2. `analysis.status` — состояние и прогресс задания.
3. `analysis.result` — терминальный результат, включая частичный результат или ошибку.

Полные машиночитаемые схемы находятся в:

```text
soika_uds/integration/schemas/v1/
```

Примеры находятся в:

```text
examples/contracts/v1/
```

## Задание на анализ

Обязательные поля:

- `contract_version`;
- `message_type` со значением `analysis.request`;
- `analysis_id`;
- `requested_at` с обязательным UTC offset;
- `territory`;
- `sources`;
- `options`;
- `allow_partial`;
- `idempotency_key`.

Территория содержит город и хотя бы один из элементов:

- адрес;
- координаты;
- GeoJSON-геометрию.

Дополнительно могут передаваться радиус и период анализа.

Неизвестные поля отклоняются. Это предотвращает молчаливое игнорирование опечаток и несовместимых изменений.

## Идемпотентность

`analysis_id` идентифицирует одно логическое задание.

`idempotency_key` идентифицирует повторную доставку того же задания. СОЙКА рассчитывает SHA-256 fingerprint семантической части запроса. В fingerprint не входит `requested_at`, поэтому технический повтор доставки не создаёт новое задание.

Если тот же `idempotency_key` используется с другим адресом, радиусом, периодом, источниками или options, СОЙКА должна вернуть конфликт идемпотентности и не начинать повторную обработку.

При отсутствии внешнего ключа Python-модель формирует детерминированный ключ:

```text
soika-v1:<analysis_id>:<sha256>
```

## Статусы

Допустимые статусы:

```text
queued
preparing
collecting
preprocessing
classifying
geocoding
filtering
detecting_events
calculating
completed
completed_with_warnings
failed
cancelled
```

Статус содержит:

- прогресс от 0 до 100;
- текущую стадию;
- номер попытки;
- количество обработанных элементов;
- общее количество элементов, когда оно известно;
- структурированные предупреждения;
- структурированные ошибки.

`completed` и `completed_with_warnings` требуют прогресс `100`.

`failed` требует хотя бы одну структурированную ошибку.

## Ошибки и предупреждения

Ошибка или предупреждение содержит:

- стабильный машинный `code`;
- человекочитаемый `message`;
- признак `retryable`;
- необязательную стадию `stage`;
- необязательные структурированные `details`.

Текст ошибки не используется как программный идентификатор. Интеграция должна принимать решения по `code` и `retryable`.

## Результат

Результат допускается только в терминальном статусе:

- `completed`;
- `completed_with_warnings`;
- `failed`;
- `cancelled`.

Стабильные разделы результата:

- `coverage`;
- `categories`;
- `topics`;
- `events`;
- `connections`;
- `timeline`;
- `messages`;
- `risk_summary`;
- `geojson`;
- `metadata`;
- `warnings`;
- `errors`;
- `provenance`.

`partial=true` означает, что часть источников или стадий не дала полного результата. Статус `completed` не может быть частичным. Для частичного успешного результата используется `completed_with_warnings`.

Отсутствие сообщений не трактуется как отсутствие проблем без учёта `coverage` и предупреждений источников.

## Происхождение результата

`provenance` содержит:

- версию СОЙКИ;
- SHA-256 digest полного набора JSON Schema;
- revisions моделей;
- версии аналитических алгоритмов.

Это обеспечивает воспроизводимость и позволяет установить, каким кодом, схемами и моделями сформирован отчёт.

## GeoJSON

Поле `geojson` всегда является `FeatureCollection`, включая пустой результат:

```json
{
  "type": "FeatureCollection",
  "features": []
}
```

Оформление карты, стили слоёв и пользовательское отображение остаются ответственностью Geo Analyzer.

## Команды проверки

Информация о контракте:

```bash
soika-uds contract info
```

Экспорт JSON Schema:

```bash
soika-uds contract export --destination ./exported-schemas
```

Проверка задания:

```bash
soika-uds contract validate \
  --kind request \
  --input examples/contracts/v1/analysis-request.json
```

Проверка статуса или результата выполняется с `--kind status` и `--kind result`.

При успешной проверке команда возвращает нормализованный JSON и exit code `0`. При ошибке возвращается структурированная ошибка и exit code `2`.

## Правила интеграции с Geo Analyzer

До отдельного этапа интеграции Geo Analyzer 2 не изменяется.

При будущем подключении Geo Analyzer должен:

1. формировать документы строго по опубликованным JSON Schema;
2. сохранять один `analysis_id` на весь жизненный цикл задания;
3. повторно использовать `idempotency_key` только для того же семантического запроса;
4. не считать ошибку СОЙКИ ошибкой основного геоанализа;
5. отображать частичный результат вместе с coverage и warnings;
6. проверять поддерживаемую версию контракта до отправки задания;
7. не зависеть от внутренних Python-классов СОЙКИ.

## Критерий завершения этапа

Этап считается завершённым, когда:

- пакет СОЙКИ содержит схемы версии `1.0.0`;
- Python-модели выполняют строгую проверку документов;
- примеры проходят contract-тесты;
- fingerprint и конфликт идемпотентности протестированы;
- частичный результат и структурированные ошибки протестированы;
- схемы экспортируются из установленного Python-пакета;
- CI проходит без изменений Geo Analyzer 2.
