# Подготовка коннекторов СОЙКА

## Граница этапа

Этап подготавливает source-specific коннекторы, но не подключает их к `ParserRunner` и не выполняет внешние сетевые запросы.

Geo Analyzer 2 не изменяется. СОЙКА остаётся backend-модулем без собственного пользовательского интерфейса.

Развёртывание предполагает один удалённый сервер для всей экосистемы: Geo Analyzer, СОЙКА, будущие модули и PostgreSQL/PostGIS. Логическая изоляция обеспечивается контейнерами, ролями базы данных, внутренней сетью и лимитами ресурсов, а не отдельной физической машиной для СОЙКИ.

## Что подготовлено

Создан каталог коннекторов российского периметра:

1. `vk` — официальный API ВКонтакте;
2. `ok` — официальный API Одноклассников;
3. `local-media` — локальные СМИ РФ через разрешённые HTML, RSS/Atom, sitemap и партнёрские выгрузки;
4. `municipal-public` — публичные муниципальные источники РФ;
5. `dzen` — подготовительный профиль Дзен;
6. `pikabu` — подготовительный профиль Пикабу;
7. `rutube` — подготовительный профиль RUTUBE.

YouTube и другие зарубежные либо ограниченные сервисы в каталог не включены.

## Разделение ядра и коннекторов

Платформа парсеров этапа 5 остаётся единственным общим ядром. Подготовленные определения описывают только особенности источника:

- разрешённые способы доступа;
- домены;
- планируемые возможности;
- обязательные options;
- формат checkpoint;
- модель стоимости;
- необходимость credentials;
- policy template;
- состояние жизненного цикла.

На следующем этапе source-specific adapters будут реализовывать `ParserAdapter` и регистрироваться в `ParserRegistry`.

## Fail-closed состояние

Все подготовленные определения имеют `network_enabled=false`.

Состояния `prepared` и `review_required` не позволяют выполнять внешний запрос. Перед интеграцией необходимо:

- завершить правовую и security-проверку;
- подготовить отдельный `SourcePolicy`;
- закрепить домены и API version;
- сформировать тестовые фикстуры;
- определить правила удаления и обновления;
- подтвердить бесплатный режим или customer-provided credentials;
- перевести connector в `ready_for_integration`.

Автоматический переход на платный тариф запрещён.

## HTML-профили локальных источников

`HtmlSourceProfile` используется для локальных СМИ и муниципальных сайтов. Он содержит:

- источник и вид источника;
- базовый HTTPS URL;
- субъект РФ и муниципалитеты;
- способ обнаружения страниц;
- список discovery URL;
- CSS-селекторы статьи и комментариев;
- URL `robots.txt`;
- признак необходимости JavaScript rendering;
- обязательное обоснование rendering;
- выключенное по умолчанию состояние.

Шаблоны находятся в:

```text
configs/connectors/local-media-site-template.json
configs/connectors/municipal-site-template.json
```

HTML является основным источником содержимого. RSS/Atom и sitemap используются как дешёвые механизмы обнаружения новых страниц и не заменяют DOM extraction.

Headless browser не является режимом по умолчанию. Он допускается только при наличии fixture, подтверждающей отсутствие нужного содержимого в статическом HTML, и после отдельного resource/security review.

## Бесплатная модель

Базовые режимы:

- `free_public`;
- `free_official_api`;
- `partner_export`.

`optional_paid` допускается только как расширение конкретного заказчика с его ключом и бюджетом. Базовый продукт не включает автоматический paid fallback.

## PostgreSQL/PostGIS

Коннекторы не записывают данные в SQL напрямую. На этапе интеграции они возвращают `SourceMessage` через общее ядро.

PostgreSQL/PostGIS будет добавлен отдельным слоем хранилища по плану разработки. Он будет работать на том же удалённом сервере, но через отдельные роли и схему СОЙКИ. Такое разделение не связывает source-specific код с конкретными SQL-таблицами и сохраняет тестируемость адаптеров.
