# Стратегия тестирования СОЙКА UDS Development

## Контуры тестирования

### Unit

Без сети, моделей, OSM и базы данных. Проверяются чистые функции, валидация контрактов, преобразование предсказаний, расчёты и обработка ошибок.

### Contract

Проверяется совместимость задания и результата с Geo Analyzer по версионированным JSON Schema.

### Integration

Используются локальные контейнеры PostgreSQL/PostGIS, Redis, mock HTTP services и локальные model fixtures.

### Controlled external

Проверяются реальные модели Hugging Face и разрешённые OSM endpoints. Эти тесты запускаются отдельно, имеют лимиты и не блокируют обычный unit CI при временной недоступности внешней сети.

### End-to-end

Geo Analyzer создаёт задание, SOIKA собирает тестовые сообщения, обрабатывает их, сохраняет результат и возвращает данные для вкладки отчёта.

### Regression and quality

Фиксированные размеченные наборы проверяют классификацию, геокодирование, состав событий и риск. Изменение модели или алгоритма не допускается без отчёта о сравнении.

### Performance

Проверяются batch inference, объём памяти моделей, большие территории, массовые сообщения, параллельные задания и длительная работа worker.

### Failure injection

Имитируются недоступность источника, timeout OSM, повреждённая модель, ошибка PostGIS, повтор задания, перезапуск worker и частичная запись результата.

## Правила

- Ни один unit-тест не скачивает модель и не обращается к интернету.
- Вероятности удалённой модели не сравниваются на точное строковое равенство.
- Внешние тесты маркируются и запускаются отдельным workflow.
- Любой исправленный дефект получает regression test.
- Формула риска тестируется на заранее рассчитанных примерах.
- Геометрические тесты всегда явно проверяют CRS.
- Результаты должны быть детерминированы при фиксированных версиях и random seed.
