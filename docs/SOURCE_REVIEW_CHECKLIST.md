# Чек-лист подключения источника СОЙКА

Этот чек-лист заполняется до начала производственного сбора.

## 1. Идентификация

- внутренний `source_id`;
- официальное название;
- владелец или оператор;
- контакт владельца;
- страны и юрисдикции;
- тип источника;
- предполагаемая ценность для анализа городской среды.

## 2. Способ доступа

Отметить один основной способ:

- официальный API;
- лицензированный feed;
- публичные веб-страницы;
- файл, предоставленный владельцем;
- ручной экспорт;
- иной способ, требующий отдельного решения.

Зафиксировать:

- endpoint или область страниц;
- авторизацию;
- пагинацию;
- временные фильтры;
- географические фильтры;
- порядок обновления;
- стабильность external ID;
- обработку удаления и редактирования;
- официальный rate limit;
- технические ограничения.

## 3. Изученные документы

Обязательный список ссылок и сохранённых digest:

- официальная документация API;
- terms of service;
- privacy policy;
- robots.txt для public web;
- лицензия на данные;
- developer agreement;
- договор;
- письменное разрешение;
- правила публикации и повторного использования;
- требования к attribution;
- требования к удалению;
- ограничения по территории и типу пользователя.

Дата review и reviewer должны быть зафиксированы.

## 4. Разрешение

Ответить отдельно:

- разрешён ли автоматизированный доступ;
- разрешён ли массовый сбор;
- разрешено ли хранение;
- разрешена ли аналитическая обработка;
- разрешено ли объединение с другими данными;
- разрешена ли передача результата Geo Analyzer;
- разрешено ли хранить исходный текст;
- разрешено ли хранить ссылки;
- разрешено ли хранить идентификатор автора;
- требуется ли attribution;
- требуется ли письменное разрешение;
- ограничен ли срок действия разрешения;
- существует ли обязанность удалить данные после прекращения доступа.

Любой ответ `unknown` блокирует production activation.

## 5. Персональные данные

Определить:

- содержит ли текст персональные данные;
- содержится ли username;
- содержится ли profile ID;
- содержатся ли контакты;
- содержится ли точное местоположение;
- возможны ли данные о здоровье, политических взглядах, религии, судимости;
- возможна ли биометрия;
- возможны ли данные детей;
- правовое основание;
- цель обработки;
- минимальный набор полей;
- срок хранения;
- место хранения;
- трансграничная передача;
- порядок удаления и исправления;
- необходимость уведомления или согласия;
- необходимость DPIA/PIA или иного assessment.

По умолчанию author ID удаляется или заменяется HMAC pseudonym.

## 6. Авторское право и права на базу данных

Определить:

- кому принадлежит текст;
- кому принадлежит база данных;
- допускается ли извлечение существенной части;
- допускается ли систематическое извлечение небольших частей;
- допускается ли хранение полного текста;
- допускается ли публикация цитат;
- допускается ли публикация агрегатов;
- требуется ли attribution;
- имеются ли ограничения на коммерческое использование;
- имеются ли ограничения на обучение моделей.

## 7. Robots и crawler policy

Для `public_web`:

- записать URL robots.txt;
- указать User-Agent СОЙКИ;
- проверить правила для этого User-Agent;
- проверить redirects robots.txt;
- сохранить дату и результат;
- определить срок кеширования;
- определить поведение при unavailable/unreachable;
- повторно проверять до запуска после истечения кеша.

Разрешение robots не заменяет terms, license или письменное разрешение.

## 8. Безопасность

Проверить:

- HTTPS;
- точную allowlist доменов;
- запрет IP literal;
- запрет private, loopback, link-local и metadata networks;
- проверку DNS;
- проверку каждого redirect;
- content-type allowlist;
- response size limit;
- timeout;
- rate limit;
- retry policy;
- отсутствие raw credentials в manifest;
- secret reference;
- запрет adapter-supplied authorization headers;
- безопасный JSON/HTML parser;
- отсутствие выполнения JavaScript;
- отсутствие shell-команд;
- отсутствие browser automation без отдельного review;
- отсутствие сохранения raw response без разрешения;
- redaction audit logs;
- controlled external tests.

## 9. Данные адаптера

Каждый объект должен формировать:

- `source`;
- `external_id`;
- `text`;
- timezone-aware `published_at`;
- исходную ссылку, если разрешена;
- author ID только в разрешённом режиме;
- координаты только при наличии основания;
- metadata только по allowlist.

Нельзя передавать произвольный dict вместо `SourceMessage`.

## 10. Отказоустойчивость

Проверить:

- стабильный checkpoint;
- повтор страницы;
- retry временной ошибки;
- permanent error;
- `429`;
- `5xx`;
- invalid JSON/HTML;
- oversized response;
- redirect outside allowlist;
- duplicate external ID;
- deleted item;
- edited item;
- empty page;
- завершение пагинации;
- restart worker;
- повторный запуск после completed checkpoint.

## 11. Решение

Production activation допускается только после фиксации:

- `permission_status=approved`;
- evidence;
- reviewer;
- `reviewed_at`;
- `review_due_at`;
- `enabled=true`;
- закрытых unresolved questions;
- passing unit tests;
- passing controlled external test;
- одобрения legal/privacy/security.

Решение должно быть отзываемым. При изменении terms, API, robots, владельца источника или состава данных источник переводится обратно в `review_required`.
