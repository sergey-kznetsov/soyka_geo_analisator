# Гибкий ввод адреса

СОЙКА не требует единственной почтовой формы адреса. Адресные компоненты должны устойчиво извлекаться из коротких строк, которые могут приходить с сокращениями, запятыми или без них.

Поддерживаемый production-подход состоит из нескольких слоёв:

1. Точные rules-v3 для форм с явными маркерами улицы, дома, корпуса, перекрёстка, района и POI.
2. Ограниченный free-form fallback для коротких строк, похожих на адрес и заканчивающихся номером дома. Он сохраняет номер дома и корпус, но не пытается трактовать произвольное предложение как адрес.
3. Natasha остаётся NER fallback для локаций в обычном тексте.
4. Известный город используется как контекст поиска и не должен становиться частью имени улицы при semantic ranking.
5. Результат проверяется геокодером. Если вход распознан на уровне `house`, street-only кандидат не считается успешным результатом: возвращается `house_candidate_not_resolved`.

Регрессиями покрыты, в частности, варианты:

```text
Ижевск Пушкинская 277
Ижевск, Пушкинская, 277
Пушкинская 277
пушкинская 277
Ижевск Пушкинская, д. 277
Ижевск, Пушкинская, 277 к 2
```

Явная форма `Ижевск, ул. Пушкинская, д. 277` продолжает обрабатываться тем же контрактом.

Free-form fallback намеренно ограничен. Строки наподобие `подъезд 2`, `квартира 277`, `сломался лифт 2` или `сегодня придут 10 человек` не должны становиться адресами только из-за наличия числа.

Для массового production-геокодирования используется собственный или договорной Nominatim endpoint. Публичный Nominatim допускается только для qualification/controlled probes согласно `docs/GEOLOCATION.md` и production registry.

Исходная строка сохраняется в результате, а нормализованные `street`, `house_number`, `kind`, альтернативные кандидаты, confidence и причины решения остаются доступны для аудита и повторного ranking.
